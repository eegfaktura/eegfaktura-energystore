# M0 — Foundation: build, hygiene, triage, CI, coverage

**Concept:** phase 0 · **Status:** done 2026-10-03 (production moves not done, ES-24) · **Production code:** build layout only (ES-22: two
entry points move to `cmd/`), generated code committed (ES-2), format-only and #11 vet fixes (ES-11), CI, test code
**Depends on:** `open-points.md` ES-2, ES-3 (tools and new actions only), ES-9, ES-10, ES-11, ES-12
(`govulncheck`), ES-22.
**Effort:** 2 – 3 days (the hang diagnosis may take a day on its own).

## Goal

`go test -race -count=1 ./...` is green from a fresh checkout, locally and in CI, deterministically —
no hang, no leftovers, no dependence on the host's time zone — and coverage cannot silently fall.
Without M0 every later milestone writes tests that CI does not run.

## Scope

1. **Reproducible build (ES-2, ES-22).** `scripts/dev/generate.sh`: `protoc` and both plugins at fixed
   versions (≥ 7 days old, dates in `AGENT_LOG.md`), generates `protoc/*.pb.go`; the generated files are
   committed; CI regenerates and runs `git diff --exit-code protoc/`. `estore.go` → `cmd/estore/main.go`,
   `initQoV.go` → `cmd/initqov/main.go`; the `Dockerfile` build lines follow; no logic changes. Then
   `go build ./...` and `go vet ./...` work. Mechanical production changes allowed here (ES-11): one
   format-only commit (`gofmt`, #47) and the two vet fixes of #11 (dead `return`, keyed literal).
2. **Test hygiene (#7, #9).** Every Badger path in tests under `t.TempDir()` (`viper.Set("persistence.path", …)`
   with `t.Cleanup` reset, and `ebow.ClosePool()` in a `t.Cleanup` registered after `t.TempDir()` so it runs
   first — the pool is a global that keeps stores open across tests); the git-ignored leftovers are removed
   and the ignore lines dropped.
   `TestMain` in each package with time-dependent tests sets `time.Local` to `Europe/Vienna`; one guard
   test fails if the zone database is missing. No `t.Parallel` in packages that use Viper or the pool.
3. **The hang (#3).** Per-package `-timeout 300s` (`calculation` alone takes 143 s under `-race`); on timeout Go prints all goroutines — record the
   blocking goroutine. Diagnose once. First suspect: `calculation` and `excel` run in parallel and share
   `test/rawdata/excelsource*` (`excel` deletes `excelsource` while `calculation` may hold it open, #3/#7) —
   `t.TempDir()` removes that; second suspect an unclosed iterator or transaction (F16); fix in test code if the test leaks, else record and `t.Skip("known-errors #3")` the one test.
4. **Triage of the red tests.** `model/mqtt_test.go` to today's wire format (#4: the contract changed,
   the test follows; M6 checks the format against eda-xp). `TestMassImport` (#5): a small fixture
   generated by the test itself, epochs computed in `Europe/Vienna`. Delete `test/rawstore_test.go` and
   `test/datasetCalc_test.go` (#6, ES-10). The six GoLand skeletons (#8) stay until
   M1 (`store`, `store/function`) and M3 (`services`, needs a store) fill them; they are listed in the
   baseline as "not a test". `TestCalculateBiAnnualParticipantReport`'s 26-bucket assertion (F8) is
   removed with a comment `// bucket count: known-errors #23, ES-14` — the correct count is a business
   answer, so the defect test comes in M3 (S6). `store/ebow.TestOpenMaxObject` is red under `-race`
   (F5): `t.Skip("known-errors #20")` until M4c; M5 adds the targeted pool tests.
5. **Test support** `internal/testsupport/`: `TempStore(t, tenant, ecId)`, `RawLine` and `CpMeta`
   builders, `CrMsg` builder (JSON → gzip → base64, as eda-xp), `Vienna` location and DST day constants,
   `InDelta` helper for kWh (T7).
6. **CI (ES-11, ES-3, ES-12).** `docker-image.yml`: the test step becomes
   `go test -race -count=1 -timeout 300s -coverpkg=./... -coverprofile=cover.out ./...` (all packages), `test -z "$(gofmt -l .)"`, `go vet ./...`,
   then `bash scripts/dev/coverage-check.sh cover.out`, `go tool cover -html` as artefact, and
   `govulncheck ./...` (reporting only). New actions (`upload-artifact`) by SHA; the tools by version.
7. **Coverage gate (ES-9).** `scripts/dev/coverage-check.sh`: statements per package from the profile,
   floors in `scripts/dev/coverage-floors.txt` (the clean baseline, rounded **down** to the full percent;
   generated code excluded), fails if one package falls below. Raised at the end of every milestone.
8. **Docs and tracking:** `HOWTO-run-tests.md` updated to the one-command form; AGENTS.md §9/§17;
   `CHANGELOG.md` (a red test now blocks the image; `estore`/`initqov` build paths); `EXTERNAL_SOURCES.md`
   (tool versions, actions); `known-errors.md` #1–#9 statuses; `AGENT_LOG.md`.

## Acceptance criteria

- From a fresh clone: `bash scripts/dev/generate.sh && go test -race -count=1 ./...` is green, twice in a row, with `TZ=UTC` and with `TZ=Europe/Vienna`.
- `git status --short --ignored` after the run shows no new file.
- `go test -count=20 ./calculation/` (without `-race`, about 5 min) passes without a hang, or the one test is skipped with `known-errors #3`.
- A deliberately red test on a throw-away branch makes the CI test job red and builds **no** image; lowering one floor by a point is green, raising it above the measured value is red.
- `grep -rnE 't\.Skip(f|Now)?\(' --include=*_test.go . | grep -v 'known-errors #[0-9]'` prints nothing.
- `git diff --stat` under `rest/`, `store/`, `calculation/`, `excel/`, `mqttclient/`, `middleware/`: only `_test.go` files, plus the format-only commit and the two #11 fixes (each its own commit).
- `gofmt -l .` and `go vet ./...` print nothing.

## Risks

- The hang is inside Badger (not a leak of ours) → needs a Badger option or upgrade: a decision, recorded.
- `-race` finds more than F5 in the old tests → each becomes a `known-errors.md` row; a race in
  production code is skipped with its number, not "fixed" in a test.
- Committed generated code drifts from the `.proto` files → the CI diff check catches it.
